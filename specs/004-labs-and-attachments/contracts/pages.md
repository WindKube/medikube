# Contract: pages and page actions (phase 004)

**Pages added: 4** (8 Playwright smoke cases at two viewports).
**Page-action routes added: 4** (research D-25).

Two of the four pages are generated by `records.Register(kind.LabResult, …)` and cost no
handwritten routing; two are hand-written.

---

## 1. The shell, unchanged

Every page renders inside the shell phase 001 built and asserts, at **1440×900** and **390×844**:

- HTTP `200`;
- `banner`, `navigation[name="Primary"]`, `main`, `contentinfo` visible;
- `combobox[name="Active patient"]` visible on every **authenticated** page (introduced by phase 002; asserted from phase 002 onward — a switcher that throws must break the gate everywhere at once, which is the desired blast radius);
- **the page's own landmark** (below) visible;
- `body[data-signals]` present, proving the Datastar runtime booted;
- **zero** browser console errors, **zero** uncaught page errors, **zero** failed network requests.

The landmarks live outside every patch target and are never morphed. Empty states render the shared
`@EmptyState(title, body, action)` **inside** the page's own landmark, so the landmark assertion
holds on a freshly seeded instance with no data — which is the most common way a smoke gate goes
falsely red.

## 3. Page-action routes

Neither navigable pages nor part of the public API. Each appears in `medikube routes` with
`Kind: page_action`, is **deliberately excluded** from `api/openapi.json`, has no ARIA landmark,
and **declares the Playwright spec that exercises it**. `e2e/routes.gate.spec.ts` fails the build
if that spec does not exist or does not reference the route.

| Route | Purpose | Response | Covering spec |
|---|---|---|---|
| `POST /documents/upload` | The native multipart upload form action (research D-24). Fields: `file`, `patient`, `owner_kind`, `owner_id`, `description`, `category`, `replaces`, `return_to` | `303 See Other` to the validated `return_to`, else `/documents`. On refusal, `303` back with the error rendered in the page's error region — the message may name the user's own file, the logs may not | `e2e/specs/documents.spec.ts` |
| `GET /documents/list` | The library table fragment: filters, paging, and the refresh after a delete, restore or describe | `200 text/html`, the table fragment with its stable id | `e2e/specs/documents.spec.ts` |
| `GET /lab-results/component-suggest` | The catalogue suggestion listbox. `?q=` (≥ 3 characters), debounced at 300 ms | `200 text/html`, a `role="listbox"` fragment; distinct fragments for "nothing matched that" and "the catalogue has not been loaded" | `e2e/specs/labs.spec.ts` |
| `GET /labs/trends/series` | The series, summary and chart fragment. `?series_key=&unit=&from=&to=` | `200 text/html` | `e2e/specs/trends.spec.ts` |

### 3.1 `return_to` is validated, not trusted

`POST /documents/upload` takes `return_to` so the redirect lands back where the user was — a record
detail page, or the library. Its value is matched against the **registered page-route patterns**
before use; anything that does not match a registered `KindPage` route is ignored and the redirect
goes to `/documents`. An unvalidated redirect target from a form field is an open redirect, and an
open redirect in an application holding medical records is a phishing primitive (research D-34).
A test feeds `//evil.example`, `https://evil.example`, `/../`, and a valid-but-unregistered path.

### 3.2 Why the upload is not Datastar

Datastar v1 binds a file input as a signal shaped `{name, contents, mime}[]` with base64 contents.
At the 32 MiB limit that is ~43 MiB of JSON held in browser memory and posted as a request body —
over the limit before the file is read. The form is therefore a plain
`<form method="post" enctype="multipart/form-data">` with no `data-on:submit` and no `data-bind` on
the file input, which also gives the browser its own upload progress for free. This is the single
transport exception in the application (research D-24, Complexity Tracking).

## 4. Content Security Policy

The application's pages keep every directive the constitution names and **gain one**:

```
default-src 'self'; script-src 'self' 'unsafe-eval'; style-src 'self';
img-src 'self'; frame-src 'self';           <-- added by this phase
frame-ancestors 'none'; object-src 'none'; base-uri 'self'; form-action 'self'
```

`frame-src 'self'` is required because the inline document viewer frames MediKube's own
`/api/v1/attachments/{id}?disposition=inline` route. It is additive: no directive the constitution
names is weakened, no external origin is admitted, and the framed response carries its own far
tighter policy (`attachments.md` §3.1).

`script-src 'unsafe-eval'` remains the accepted, permanent trade-off — Datastar compiles
expressions with the `Function` constructor. The Datastar inline-script SDK family
(`ExecuteScript`, `ConsoleLog`, `ConsoleError`, `Redirect`, `DispatchCustomEvent`, `ReplaceURL`,
`Prefetch`) remains banned by `forbidigo`: each appends a literal inline `<script>`, each fails
under `script-src 'self'`, and each failure logs a CSP violation that would fail the console gate.
